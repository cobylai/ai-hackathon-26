# Log: feature/web-search

- S1: `harness/search/google.py` parses organic results from `<a>` wrapping `<h3>` (old `div.g` and current markup); drops ads, "People also ask" cards and results beyond 2 per domain; snippets cut to 120 chars. `__init__.py` starts the package.
- S1 note: Google served `/sorry/` bot walls to both plain fetch and headless Chromium, so `tests/pages/google_results.html` is a real 2019 results page (query "test", 10 results) saved from the Wayback Machine instead of retrying the wall.
- S2: `ddg.py` parses `html.duckduckgo.com` results, unwrapping `/l/?uddg=` links and dropping `result--ad` blocks; `engine.search()` tries Google, falls back to DDG on a non-OK page or zero results, and keeps DDG for 10 minutes (`engine.in_fallback()`, `last_status`).
- S2 note: html.duckduckgo.com answered curl with HTTP 202, its own bot check, so the DDG fixture is a Wayback copy of the "python" results page (13 organic results, python.org twice, which exercises the per-domain cap).
- S3: `harness/search/tools.py` adds `search` (numbered `title (domain) snippet` lines, list trimmed to fit the 1500 cap, only shown results stay openable) and `open_result(n)` (opens through the shared browser, returns status line plus first page of text).
- S3 note: registry entries required updating the exact TOOLS set assertion in `tests/test_tools.py`. Search got its own group `search` rather than joining `web`, which already holds six browser tools, against the five-tool rule.
- S4: `rank.py` splits text on paragraph boundaries into ~600-char chunks (long paragraphs cut at sentence/word breaks) and scores them with `rank-bm25` over lowercased, stop-word-filtered question terms; `top_chunks()` returns the best k in page order, and the opening chunks when nothing matches.
- S5: `harness/llm.py` adds `ask(prompt, choices, max_tokens)` against `LLM_BASE_URL`/`LLM_MODEL` (OpenAI chat completions), requesting a JSON enum when `choices` are given, mapping replies back onto them, and returning "" on any transport or parse failure; `FakeLLM` scripts replies. Shape matches the overview seam (`ask`, `FakeLLM`).
- S5: `prompts.py` adds pick/note/enough/rewrite with tolerant parsing: out-of-range or duplicate numbers dropped, NONE/empty means no note, YES/NO coerced, a blank rewrite keeps the old query.
- S6: `loop.py` runs search -> pick -> open -> top-2 BM25 chunks -> note -> enough/rewrite, capped at 3 rounds x 3 pages x 10 results; skips already-opened URLs and BLOCKED/ERR pages, stops when a rewrite repeats a query, and answers in at most 120 words with a numbered `Sources:` line.
- S6 note: notes are numbered in collection order, not by search-result number, so citations always match the Sources list. `research` was added to `registry.py` (`GROUPS["search"]`, now three tools) even though S6's file list omitted it, otherwise the decision tree could not call it; the exact TOOLS-set assertions in `tests/test_tools.py` and `tests/test_search_tools.py` were updated.
- S7: `cache.py` keeps extracted text in SQLite (`~/.harness/cache.db`, override `HARNESS_CACHE_DB`) keyed by URL with a 24-hour TTL; `tools.open_page` checks it before navigating and stores only OK pages, so `open_result` and the `research` loop get it for free. A locked or broken cache returns None and never raises.
- S7 note: `tests/conftest.py` gained an autouse fixture pointing `HARNESS_CACHE_DB` at a per-test tmp file, so tests never write the real `~/.harness/cache.db`.
- S8: live eval with `qwen/qwen3.5-9b` over 12 questions: 4/12 pass. Questions 7 to 12 opened 0 pages because Google walled us (`/sorry/`) and DuckDuckGo's HTML endpoint served its own "select all squares containing a duck" challenge, which `classify` calls OK, so `search` returned 0 results and the 10-minute fallback kept serving that page.
- S8: the six questions that reached the web scored 4/6, median 20.1 s and median 10,661 input chars per question (targets under 20 s and 8,000 chars, both narrowly missed); 27 pages, 1 BLOCKED. q02 and q04 failed because the answer sentence was not in the two BM25 chunks that were read.
- S8 note: the local model is a reasoning model and returns empty content until `reasoning_effort: none` is sent, so `llm.ask` now forwards `LLM_REASONING_EFFORT` (additive, tested). Full table and five suggested fixes in docs/plan/notes-search-eval.md.
- S8 fix 1: `state.BLOCKED_PHRASES` now recognises DuckDuckGo's challenge text ("bots use duckduckgo too", "confirm this search was made by a human", "select all squares containing"), so a walled fallback classifies BLOCKED instead of OK-with-zero-results.
- S8 fix 2: `engine.search` only remembers DuckDuckGo for the ten-minute window when it actually returned results, and clears the window when both engines fail (or when a remembered fallback stops answering), so a walled fallback can no longer pin every later query.
- S8 fix 3: `rank.top_chunks` with k>=2 always keeps the page's opening chunk and lets BM25 fill the remaining slot, so definitions and dates in the first paragraph are read even when the question words are spread over a long page; k=1 still returns the single best chunk.
- S8 fix 4: the loop opens at most 2 pages per round (was 3); the third page rarely changed an answer in Run 1 and dominated the model input (q05: 14 calls, 15.6k chars).
